## 🔄 Процедура безопасной публикации

### Шаг 1: Подготовка проекта
```bash
# 1. Убедитесь, что .gitignore актуален
git status --ignored

# 2. Проверьте, что конфиденциальные файлы не отслеживаются
git ls-files | grep -E "(input|logs|analytics|quality_analysis|metadata|output|archive)" | wc -l
# Должно быть 0 файлов

# 3. Очистите кэш git при необходимости
git rm -r --cached input/ logs/ analytics/ quality_analysis/ metadata/ output/ archive/ --ignore-unmatch
```

### Шаг 2: Проверка безопасности
```bash
# 1. Проверьте размер репозитория (должен быть ~50 MB, не 6+ GB)
du -sh .git

# 2. Убедитесь, что в репозитории только безопасные файлы
git ls-files | wc -l
# Должно быть ~40 файлов

# 3. Проверьте, что конфиденциальные файлы остались локально
ls -la input/ logs/ analytics/ quality_analysis/
# Должны существовать локально
```

### Шаг 3: Публикация
```bash
# 1. Сделайте коммит с изменениями
git add .
git commit -m "🔒 SECURITY: Update .gitignore and remove confidential data from tracking"

# 2. Загрузите в GitHub
git push origin main
```

## 🚨 АВАРИЙНЫЕ МЕРЫ

### Если конфиденциальные данные попали в репозиторий:

```bash
# 1. Удалите файлы из git (но оставьте локально)
git rm -r --cached input/ logs/ analytics/ quality_analysis/ metadata/ output/ archive/

# 2. Сделайте коммит
git commit -m "🔒 SECURITY: Remove confidential data from public repository"

# 3. Принудительно загрузите исправленную версию
git push --force-with-lease origin main

# 4. Проверьте, что файлы удалены из GitHub
git ls-files | grep -E "(input|logs|analytics|quality_analysis)" | wc -l
# Должно быть 0
```

### Если нужно восстановить репозиторий:
```bash
# 1. Удалите локальный репозиторий
rm -rf .git

# 2. Пересоздайте репозиторий
git init
git remote add origin https://github.com/FUYOH666/Scanovich.ai-audio-call.git

# 3. Добавьте только безопасные файлы
git add .
git commit -m "feat: Clean ASR-4.5 project - source code only"

# 4. Загрузите чистую версию
git push -u origin main
```

## 🔒 Безопасность репозитория

### Репозиторий приватный:
- ✅ Доступ только авторизованным пользователям
- ✅ Дополнительная защита от случайного доступа
- ✅ Можно хранить чувствительную информацию

### Мониторинг изменений:
- Следите за размером репозитория
- Регулярно проверяйте `git ls-files` на наличие конфиденциальных данных
- Используйте pre-commit хуки для предотвращения случайной публикации

## 📋 Чек-лист перед публикацией

- [ ] `.gitignore` актуален и включает все конфиденциальные пути
- [ ] Конфиденциальные файлы не отслеживаются git'ом (`git ls-files` проверен)
- [ ] Размер репозитория < 100 MB (оптимально ~50 MB)
- [ ] В репозитории только исходный код и документация
- [ ] Конфиденциальные данные остались локально
- [ ] Коммит содержит описание изменений
- [ ] Тестирование прошло успешно
