## 🎯 Цель анализа

Объективная оценка качества работы администраторов МРТ-центра по утверждённым скриптам обслуживания.

**Что оценивается:**
- Следование скрипту (30 критериев)
- Профессионализм и soft skills
- Полнота информации клиенту
- Качество консультации

**Результат:**
- Итоговый балл 0-100
- Детальные комментарии по каждому критерию
- Конкретные рекомендации для улучшения
- Статистика по администраторам

---

## 📋 Критерии оценки (30 пунктов)

### Блок 1: Приветствие и установление контакта (15%)

1. Название центра в приветствии
2. Имя администратора
3. Доброжелательное приветствие
4. Уточнение имени клиента
5. Вежливое обращение

### Блок 2: Сбор информации (20%)

6. Жалобы/симптомы клиента
7. Длительность симптомов
8. Характер боли
9. Визит к врачу

### Блок 3: Консультация и рекомендации (25%)

10. Формулировка запроса клиентом
11. Рекомендация администратора
12. Аргументы в пользу рекомендации

### Блок 4: Запись и оформление (20%)

13. Выбор клиента
14. Дата записи
15. Время записи (с предложением вариантов!)
16. Персональные данные (ФИО, телефон, вес)
17. Противопоказания
18. Подготовка и документы
19. Адрес центра

### Блок 5: Финансы (10%)

20. Стоимость исследования
21. Стоимость носителя отдельно (!)
22. Видеозаключение (объяснение)
23. Скидки/льготы

### Блок 6: Soft skills (10%)

24. Повторение итогов
25. Вежливость и тон
26. Уточнение удобства времени
27. Альтернативы при отказе
28. Причина отмены
29. Контакты для связи
30. Профессионализм

## 🏥 Различия скриптов 1.5T и 3T

### Скрипт 1.5T (базовое оборудование):
- Акцент на стандартные протоколы
- Стандартная консультация

### Скрипт 3T (премиум оборудование):
- **Критично:** Аргументы в пользу 3T
  - Высокое разрешение
  - Ранняя диагностика
  - Детализация
- Премиум-сервис и сопровождение

## 💻 CLI Команды

### 1. Анализ одного звонка

```bash
./venv/bin/python main.py analyze-quality output/звонок.txt
```

**Опции:**
- `--show-reasoning` - показать reasoning от Claude

**Результат:**
- Итоговый балл
- Сильные стороны (Top 5)
- Области для улучшения (Top 5)
- Стоимость анализа
- Сохранение в `quality_analysis/individual/`

### 2. Пакетный анализ

```bash
./venv/bin/python main.py analyze-batch
```

**Опции:**
- `--admin-name "Имя"` - только для конкретного администратора

**Результат:**
- Анализ всех транскрипций в output/
- Итоговая статистика (обработано/пропущено)
- Общая стоимость

### 3. Отчёт по администратору

```bash
./venv/bin/python main.py report "Анастасия" --period week
```

**Периоды:**
- `day` - 1 день
- `week` - 7 дней (по умолчанию)
- `month` - 30 дней

**Результат:**
- Markdown отчёт в `quality_analysis/reports/`
- Средний балл за период
- Top 5 сильных сторон
- Top 5 областей для улучшения
- Лучшие/худшие критерии

### 4. Статистика стоимости

```bash
./venv/bin/python main.py cost-stats
```

**Опции:**
- `--period week/month` - период

**Результат:**
- Общее количество проанализированных звонков
- Токены (prompt/completion)
- Общая стоимость
- Средняя стоимость на звонок
- Статистика по администраторам

## 📊 Интерпретация результатов

### Шкала оценок:

| Балл | Уровень | Описание |
|------|---------|----------|
| 90-100 | Отлично | Идеальное следование скрипту |
| 80-89 | Хорошо | Высокий профессионализм, минимальные упущения |
| 70-79 | Удовлетворительно | Базовые требования выполнены |
| 60-69 | Требует улучшения | Существенные пропуски в скрипте |
| <60 | Неудовлетворительно | Критические нарушения скрипта |

### Что означает `relevant: false`:

Критерий неприменим к конкретному звонку. Например:
- Клиент не упоминал боль → критерий "Характер боли" = irrelevant
- Клиент сам отказался от услуги → критерии продаж = irrelevant

**Не влияет на итоговый балл** (исключается из расчёта).

### Как читать `strengths` и `weaknesses`:

- **Strengths:** Конкретные действия администратора, выполненные хорошо
- **Weaknesses:** Пропущенные пункты скрипта или ошибки
- **Recommendations:** Действенные советы для улучшения

## 🎯 Best Practices

### Для администраторов:

1. **Всегда предлагайте варианты** (не спрашивайте "на когда?", а "Есть 15:00 или 19:00")
2. **Объясняйте видеозаключение** - клиенты не знают что это
3. **Озвучивайте носитель отдельно** - не объединяйте с ценой исследования
4. **Уточняйте льготы** - пенсионеры, инвалиды
5. **Повторяйте итоги** - дата, время, адрес, стоимость

### Для руководителей:

1. **Анализируйте еженедельно** - `report "Имя" --period week`
2. **Фокусируйтесь на паттернах** - одинаковые ошибки у всех
3. **Внедряйте best practices** - от лучших администраторов
4. **Обучайте на конкретных примерах** - ссылки на звонки
5. **Отслеживайте динамику** - улучшение со временем

## 🔧 Troubleshooting

### Claude недоступен

```
Error: Connection to OpenRouter failed
```

**Решение:**
- Проверьте API ключ: `echo $OPENROUTER_API_KEY`
- Проверьте интернет: `curl https://openrouter.ai`

### Некорректный JSON от Claude

```
Error: Failed to parse Claude response
```

**Решение:**
- Автоматически retry (3 попытки)
- Проверьте логи: `logs/errors.log`

### Скрипт не найден

```
Error: Script not found
```

**Решение:**
- Проверьте наличие файлов:
  - `script установлены 1.5T.md`
  - `script установлены 3T.md`
