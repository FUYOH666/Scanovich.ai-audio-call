## ✅ **РЕШЕНИЕ: Миграция на systemd сервисы**

### 🎯 **Преимущества systemd сервисов:**

1. ✅ **Независимость от пользовательской сессии** — работают даже если никто не залогинен
2. ✅ **Автозапуск при загрузке системы** — не нужно вручную запускать после перезагрузки
3. ✅ **Автоматический перезапуск при падении** — `Restart=always`
4. ✅ **Централизованное логирование** — `journalctl -u service-name`
5. ✅ **Управление зависимостями** — ASR запускается только после VLLM
6. ✅ **Graceful shutdown** — корректное завершение процессов при остановке
7. ✅ **Ограничение ресурсов** — контроль CPU/Memory через systemd

Сервис уже создан: `systemd/vllm.service`

## 🆘 **Troubleshooting**

### **Проблема: Сервис не запускается**

```bash
# 1. Проверить статус
sudo systemctl status service-name.service

# 2. Проверить логи
journalctl -u service-name.service -n 50

# 3. Проверить синтаксис сервиса
systemd-analyze verify /etc/systemd/system/service-name.service

# 4. Перезагрузить systemd
sudo systemctl daemon-reload
```

### **Проблема: Сервис падает при запуске**

```bash
# 1. Проверить права доступа
ls -la /path/to/working/directory

# 2. Проверить наличие venv
ls -la /path/to/venv/bin/python

# 3. Проверить переменные окружения
systemctl show service-name.service | grep Environment

# 4. Запустить вручную для отладки
cd /path/to/working/directory
./venv/bin/python script.py
```

### **Проблема: GPU не доступен в systemd сервисе**

```bash
# Добавить в сервис:
Environment="CUDA_VISIBLE_DEVICES=0"

# Проверить доступность GPU
nvidia-smi
```
